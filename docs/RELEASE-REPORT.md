# Release report — not a release

## Implemented in source (built; live hosting unverified)

Local server definitions with GUID folders and atomic JSON, catalog port uniqueness on creation, Java discovery in PATH/JAVA_HOME and /usr/lib/jvm, Mojang release metadata and SHA-1-verified server download, explicit per-server EULA prompt, single-server foreground process runner with redirected console streams, readiness and graceful stop, PID/start-time survivor check, per-server lock, an Avalonia inventory and desktop controls for default-world backups. Multiple separate CLI invocations are intended to run independent servers. Fixture checks passed in GitHub Actions, not locally. They include fake-process lifecycle/isolation checks and backup/recovery and archive-safety checks; they do not exercise real Minecraft.

## Verification

Environment: Debian 12 x86-64 sandbox, no desktop session, .NET SDK or Java. No Kubuntu desktop version, KDE, display backend, actual server launch or loader was tested. Local `dotnet restore`, build, test, publish, Java and live server execution could not be run. Outbound access to NuGet, Microsoft SDK downloads and Mojang was unavailable. GitHub Actions [run 41666778179](https://github.com/cfspearn81-code/MinecraftHostingProgam/actions/runs/41666778179) on ubuntu-24.04 x86-64 passed restore, Release build, fixture tests, and self-contained linux-x64 publishing at commit fd43ad5. Its explicitly enabled download-only job used Temurin Java 21 to resolve official metadata for Minecraft 1.21.1 and download and verify the actual server JAR against Mojang’s published SHA-1. It did not start Minecraft or accept the EULA, and deleted the test data. The exact Java 21 patch level is unavailable because detailed CI logs redirect to a blocked host. Earlier runs also passed. Shell syntax checks passed for all packaging scripts, and a Debian shell smoke test verified installation and uninstallation from a path with spaces while preserving server data; it did not launch the application or test KDE. The uploaded preview artifact was not runnable or downloadable in the sandbox because its Azure blob host was blocked; it has not been tested on a desktop. CI emitted Node 20 action deprecation warnings and reported setup-java v4 as deprecated. No screenshots or binaries were generated locally. No live EULA acceptance occurred. A container/CI build is not Kubuntu desktop verification.

## Not implemented or not verified

This is not the requested complete product. Native Wayland/XWayland, X11, fractional scaling, keyboard accessibility, .desktop launcher and native runtime dependencies remain unverified. The desktop has no onboarding, selected-server tabs, server start/stop controls, console or server shutdown handling. World-backup controls have not been run in a graphical session. There is no server edit, duplicate, delete, persistent state machine, descendant tracking, full crash recovery, configurable data root UI, reliable memory/CPU/player metrics, port collision checks for auxiliary ports, memory budget warning, or detailed progress/cancellation across all operations. Process ownership has a crash window immediately after launch; never trust it to safely manage valuable data. Port preflight has an unavoidable bind race. Java architecture detection and managed runtime installation are absent. Fabric, Forge, NeoForge, mods, players, property editor, world import/export, full-server backups, full diagnostics and networking UI are absent. A default-world-only backup/restore implementation has been added, but real-world and crash-recovery tests remain unverified; see PROGRESS.md for its limits. The exact compatibility of later Java versions is not inferred; exact major is conservatively required. Installer metadata is not cryptographically authenticated beyond HTTPS and the upstream SHA-1 artifact digest. Schema migrations and durable fsync are absent. Real live-server integration, real loader, Java distribution, UI, desktop and comprehensive race/crash tests requested in the specification have not been performed. The fixture executable covers only its named mock-process and backup checks. No screenshot may be represented as a finished product.
